# experiments/artifacts/deep100M — prebuilt inputs for the AE core scenario

The graphs consumed by `configs/ae/*.yaml` are the result of a 150-iteration
update stream (1M inserts + 1M deletes per iteration, consolidate every 5) over
the first 100M vectors of DEEP1B. Rebuilding them takes **days** (Phase B-full in
REPRODUCE.md), so the artifact ships them as a separate data bundle.

## Layout expected by the pipeline

```
artifacts/deep100M/
├── graph/checkpoints/
│   ├── iteration150            iteration150.tags   iteration150.frozen          ← Balanced arm  (~24 GB)
│   └── lits_k4_iter150         lits_k4_iter150.tags lits_k4_iter150.frozen lits_k4_iter150.labels ← SparsePath arm (~25 GB)
├── gt/
│   ├── gt_iteration150_K10_Q10000.{npy,json}  gt_iteration150_K10_Q10000_queries.npy
│   └── gt_lits_k4_iter150_K10_Q10000.{npy,json}  gt_lits_k4_iter150_K10_Q10000_queries.npy   (~35 MB total; the lits_* files are symlinks to the iteration150 ones — same active set)
├── partition/4_partitions_{round_robin,lits_balanced}/        ← regenerated by prepare_data.sh (minutes)
├── colocation/4_partitions_{round_robin,lits_balanced}/<variant>/  ← regenerated (tens of minutes, ~32 GB per partition / ~130 GB per arm)
└── pq/M24_active/                                              ← regenerated by `--stages pq_build` (SparsePath arm)
```

Checkpoints are **data-less**: graph + `.tags` (+ `.frozen` start point, `.labels`
cluster labels for LITS). Vectors are recovered from the base file as
`base[tag - 1]`, which is why `dataset.base_file` must be the same 300M slice
the graphs were built from (`DEEP1B/deep300M_base.fbin`).
